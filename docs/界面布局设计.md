# 界面布局与食堂交互设计

日期：2026-10-16。使用项目 `frontend-design` skill。

## 视觉方案与复核

场景为学生日常校园事务与一餐点选。采用白色校园便笺与墨蓝服务台的方向，用可辨识的餐盘插画表达食堂内容。基色雾白 #F3F5F9、正文墨蓝 #203149、主色靛蓝 #2848A5、薄荷 #CFE5D8、麦黄 #F2D06B、白色 #FFFFFF。中文正文采用本机 Microsoft YaHei / PingFang SC，标题用 STZhongsong / Songti SC 的校园书卷感，数字用 Segoe UI。主要文字左对齐，正文以可读行宽为准。

初稿复核去掉了通用的全大写眉题、无业务顺序的导航编号和每段相同卡片边框。把视觉重心集中到 AI 餐盘推荐区，常规菜品保持清晰网格；购物车作为安静的常驻侧栏，分区靠留白与字号区分。全站沿用统一导航、清楚的表单/表格和聊天层级，避免食堂与其他页面割裂。

桌面布局：

```text
侧栏导航 | 页面标题与当前身份
         | AI 推荐：标题 / 身体状态 / 生成按钮 / 餐盘插画
         | 三个推荐方案（生成后展示）
         | 菜品分类 + 搜索                  | 本餐购物车
         | 菜品插画 / 名称 / 营养 / 加入   | 份数 / 合计 / 提交
```

窄屏收为单列，主操作完整可点击、购物车位于菜品区域后方并提供页内定位；顶部导航横向可滚动，避免挤压正文。所有视觉插画为项目自己的 SVG 组件，不加载第三方图片，不为不存在的菜品编造图片内容。支持键盘焦点及减少动态效果设置。

## 交互约束

推荐生成与手动购物车操作使用独立加载状态；手动购物车改动可在等待 AI 时完成，最终选用方案才整体替换。后端按同一会话锁串行化购物车更新，AI 网络请求不占用购物车锁；生成结果只更新推荐，不覆盖用户在等待过程中选择的菜品。所有订单由食堂内“提交订单”按钮显式确认。


## 2026-11-10 本次用餐要求

在既有食堂 AI 主视觉文字区、生成按钮之前增加带标签的两行输入框，示例为“有荤有素，2菜一汤，主食是米饭”。显示300字符上限和“仍遵循个人忌口”的提示；生成过程中禁用编辑以避免输入与结果错位，失败保留原输入。沿用现有字体、配色和响应式布局。

菜单分类及管理员类别增加“汤”，使用本地汤碗 SVG 插画；推荐卡片逐项展示主食、配菜和汤，数量不再固定三项，购物车仍展示所有条目和份数。


## 2026-11-10 推荐条件核对

按钮改为“生成膳食方案”；推荐标题按实际1～3种显示。卡片前增加由后端验证数据生成的“本次搭配条件”，显示数量、主食、必选/任选/排除和营养界限；少于三种时说明没有放宽条件或重复凑数。长条件在窄屏换行。


## 2026-11-11 服务台界面优化

使用frontend-design技能，先制定色彩/字号/布局方案再实现。保留校园蓝#2848A5、墨蓝#203149、雾白#F3F5F9、白#FFFFFF、薄荷#CFE5D8和麦黄#F2D06B；深蓝导航提供固定方向，正文使用高对比深色，宋体类标题与Microsoft YaHei/PingFang正文分工。主要信息左对齐，正文14～15px，辅助字至少12px，手机输入16px避免缩放。审查初稿后去掉无业务意义的统计和装饰标签，突出办事入口、真实身份与资料完整度。

布局：桌面左侧深蓝导航＋顶部位置/日期＋白色操作区域；助手欢迎区以请假/借书/课表三个有说明的按钮呈现；食堂保留餐盘主视觉并增加只填入、不自动提交的要求示例；个人中心展示真实姓名/学号/班级及身体资料完成状态。登录页加入本地校园建筑SVG和密码显示切换。

管理编辑改用原生dialog弹窗，焦点限制在窗口，关闭恢复原位置；保存期间禁止关闭。学生管理增加姓名/学号/班级搜索，重置密码后同步刷新列表。手机表格在自己的容器横向滚动，主体保持无横向溢出；长文字换行、可见键盘焦点、减少动态效果继续支持。外壳及新组件样式归于workspace.css，不加入第三方字体/图片依赖。
