## 使用约定

- 以根目录 `项目要求.txt` 的功能要求为原始依据，新文档不记录其密钥内容。
- “明确要求”来自原始要求及用户后续明确补充；“建议默认”是为了落地补充的实现规则，尚未获得用户确认；“待确认”不能视为已确定需求。
- 管理员预置、学生注册、简单借还书、个人中心身体信息及购物车下单已确认；后端 Java、前端 Vue 已确认，框架、数据库及发行形式仍为建议。
- 需求变化先更新需求规格说明书，再同步数据库和验收清单。
- 本阶段只编写文档，不开发业务代码、不调用真实模型接口。

## 本次确认与下一步

- 校园知识问答、校园服务助手是两个独立入口与对话窗口；前者采用 RAG 回答知识，后者通过受控工具处理请假、借书、本人课表查询。跨模块请求提供跳转入口，会话及工具分别管理。
- 请假助手追问缺项，自动填写表单并在对话内展示，用户可修改，点击确认提交后才生成待审批申请。姓名、学号直接使用登录信息。
- 管理员账号预置；学生自行注册，只填姓名、学号、密码，以学号登录。
- 借书与还书直接完成，保持简单，不增加审批或复杂图书馆规则。
- 身体数据在个人中心维护；AI 推荐前检查完整性，不齐全提醒补全。
- 按一顿饭推荐，沿用每次三个套餐；选择一个加入购物车，在购物车提交后记录简单订单。
- 购物车建议一次保留一个套餐，可移除或替换，临时保存、不增加数据库表；多套餐及数量编辑未列入当前简单设计。
- 成品须在另一台电脑正常运行；建议 Java 21 + Spring Boot + Vue 3 + SQLite，前端构建进 JAR，配置和数据库外置，提供启动脚本。
- 两台电脑均为 Windows，优先提供 Windows 运行包；知识问答已确定采用向量检索 RAG，管理员按条保存资料时自动向量化，回答必须依据数据库原文，未找到或材料不足时明确提示未查询到。
- 建议 SQLite 保存原文及向量，Java 计算相似度，不增加独立向量服务；embedding 模型及接口尚待选定，与聊天模型分别配置。
- 下一步明确数据库和发行方式；可以安装 Java 后运行，也可以附带适用于目标系统的 Java 运行时；参见技术选型说明。

其他建议默认仍在正文标出，可继续调整。
