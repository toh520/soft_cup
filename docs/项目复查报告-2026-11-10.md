## 4. 已确认问题及建议顺序

### 4.1 优先处理：切换账号后旧 AI 回复可能显示给新账号

位置：`code/frontend/src/modules/assistant/composables/useAssistantConversation.js` 第 6～20 行；知识问答 composable 也采用相同的异步写回方式，但本次只对助手完成了动态复现。

复现：账号 A 发起请假对话，浏览器暂缓交付已经生成的响应；等待期间退出并用账号 B 登录；随后释放 A 的响应。页面左下显示林悦 `20260002`，请假卡片却显示张晨 `20260001` 及原草稿内容。此测试只控制响应交付时序，响应内容由真实 Java 后端和测试模型夹具产生。

原因：退出事件清空数组，但未取消旧请求，也未为异步结果绑定登录代次；旧 Promise 完成后继续写入模块级共享消息数组。重新登录时再次清空数组也不能阻止更晚返回的结果。

后端确认令牌隔离有效：点击旧卡片确认返回“确认已失效”，未发生跨账号业务写入。但姓名、学号、请假内容可能在前端泄漏，不能视为会话隔离完全通过。建议为请求绑定会话代次/账号，切换登录时作废请求，并在成功、失败及结束回调前校验代次；助手和知识问答同步处理。

### 4.2 图书搜索对内部空格敏感，影响自然语言查书

位置：`code/backend/src/main/java/com/toh520/campus/module/library/repository/LibraryRepository.java` 第 17～19 行。

实测 `GET /api/books?query=Java程序设计` 返回 0 条；`Java 程序设计` 和 `Java` 都返回 2 条。数据库书名为“Java 程序设计”，当前搜索为原始连续子串 `LIKE`。真实助手在不带空格的问法下也返回未找到。

建议统一书名和检索词的空白处理，或使用受控分词匹配，并补充“带空格/不带空格等价书名”的回归测试。短关键词“Java”可作为当前演示的临时用法。

### 4.3 当前电脑直接双击启动失败

位置：`code/start-campus.ps1` 第 68～83 行。

当前 PATH 的 `java` 是 Microsoft JDK 17.0.21，`mvn` 也不在 PATH；本机另有 JDK 21 和 Maven 3.9.9。脚本选择第一个存在的 Java 后才校验版本，找到 Java 17 就退出，不会继续尝试后面的 JDK 21 候选。

直接执行 `code/start-campus.cmd -NoBrowser` 实测失败，提示需 JDK 21。仅在本次启动进程中指定已有 JDK 21 后，启动成功；第二次启动正确复用同一服务。这不是应用源码无法运行，但当前电脑的无配置一键启动体验不成立。

临时启动方式见环境清单新增章节。后续可明确配置系统 `JAVA_HOME`，或者改进脚本对候选 Java 版本的筛选；本次未修改系统设置或启动脚本。
