## 2. 当前技术方案

Java、Vue 为已确认方向，其余为结合移机要求的建议：

| 部分 | 方案 | 原因 |
| --- | --- | --- |
| 前端 | Vue（已确认）；建议 Vue 3 + Vite + 成熟组件库 | 构建产物可由后端统一提供 |
| 后端 | Java（已确认）；建议 Java 21 + Spring Boot | 提供业务接口、模型 HTTP 调用和静态页面 |
| 数据库 | 建议 SQLite + SQLite JDBC，简单 JDBC 或 MyBatis 访问 | 无额外数据库服务，便于携带数据移机 |
| 模型 | Java HTTP 客户端或兼容 SDK | 对接给定服务，开发阶段验证兼容性 |
| 交付 | 建议可执行 JAR + 外部配置 + 外部数据库 + 启动脚本 | 运行端无需 Node.js、Maven 或 IDE |
| 测试 | 后端业务自动化测试 + 浏览器主流程测试 | 覆盖状态、事务、权限和界面确认 |

如果学校规定 MySQL，优先服从学校要求，改用独立数据库或 Docker Compose 交付，需求和逻辑模型保持不变。

智能功能实现及移机方案见 [技术选型说明](技术选型说明.md)。本次只更新文档，不开始编码。

## 4. 配置规范

建议 Java 项目使用外部 `config/application-local.properties` 保存本地私有配置，由启动脚本启用 `local` profile，或从操作系统环境变量读取密钥；仓库提交无密钥的配置模板。Spring Boot 不会默认自动读取 `.env` 文件，若采用 `.env` 必须显式实现加载。示例仅用于后续配置模板：

```properties
llm.api-key=${LLM_API_KEY:}
llm.base-url=https://ws-q3rjjrz12pav2w64.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
llm.model=qwen3.8-flash
llm.timeout-seconds=30
spring.datasource.url=jdbc:sqlite:./data/campus.db
app.timezone=Asia/Shanghai
app.session-secret=${SESSION_SECRET:}
```

- 本地真实密钥和会话密钥不提交；`SESSION_SECRET` 的具体需要取决于最终登录实现；模型配置与会话配置为应用自定义项，开发时需实现绑定。
- 不使用前端 `VITE_*` 变量存储模型密钥，前端只能调用后端。
- 原始 `项目要求.txt` 已包含真实 Key，默认加入 Git 忽略规则；不要将其作为课设提交附件。
- 建议撤销并更换已写入原始文件的 Key；Git 忽略规则不能撤销已泄露凭据，也不能移除历史已提交内容。
- 未配置密钥时允许普通业务运行，智能入口明确显示配置不可用；错误信息不得打印密钥。
- 不自动调用真实服务进行批量测试，常规测试使用模拟模型响应；最终再进行小规模真实调用验收。

## 5. 演示数据要求

所有内容均为虚构演示数据，校园政策应标明为演示规则，不冒充真实学校规定。

| 数据 | 建议数量与覆盖 |
| --- | --- |
| 账号 | 初始化预置一个管理员；通过注册建立两个学生，用于验证注册和身份隔离；可另提供可选学生种子数据 |
| 班级 | 一个班级，两个学生均归属该班级 |
| 课表 | 至少五条课程，至少一个无课日 |
| 图书 | 至少六种，覆盖零库存、仅一本、同名不同作者 |
| 菜品 | 各类至少四种，含素食蛋白菜、常见过敏原和下架菜品 |
| 知识 | 至少十二条，覆盖规章、课程、活动以及无答案的问题 |
| 业务记录 | 初始化可为空，通过演示流程创建，不预填虚假成功记录 |

菜品数量不等于必然能产生三个合法组合。验收前必须用演示学生的身体参数实际计算候选，确认一般、素食和指定禁忌场景有可演示数据；同时准备一个候选不足场景。

## 6. 扩展测试清单

### 身份和输入

- [ ] 姓名、学号、密码即可注册学生，身体信息初始为空。
- [ ] 重复学号注册被拒绝；并发注册同一学号只创建一个用户。
- [ ] 学号前导零不丢失，学号及密码符合约定校验；使用注册学号和密码可登录。
- [ ] 注册接口提交管理员角色不能获得管理员权限。
- [ ] 未登录不能访问学生或管理接口。
- [ ] 学生请求管理员接口被拒绝。
- [ ] 学生修改请求中的记录 ID、用户 ID 无法读取或修改他人数据。
- [ ] 名称、理由、正文仅空白时被拒绝；数字、时间、枚举按后端规则校验。
- [ ] 请假时间倒置、课表冲突、负库存和负营养值无法保存。
- [ ] 模型输出、知识正文和菜品名称作为安全文本展示。

### 业务一致性

- [ ] 最后一本书的两个并发借阅请求只有一个成功。
- [ ] 同一借阅确认令牌重复请求只产生一条记录。
- [ ] 同一图书未归还时重复借阅被拒绝。
- [ ] 同一归还请求只增加一次库存，归还后可以再次借阅。
- [ ] 两次冲突审批只有第一笔待审批状态更新成功。
- [ ] 下单写入中途失败时，不留下只有主表或部分明细的订单。
- [ ] 历史订单保留下单时的菜名、份量和营养，不受管理员修改影响。
- [ ] 身体信息缺失时显示缺项及个人中心入口，不发起模型调用；补全后可推荐。
- [ ] 加入购物车不创建订单；重复加入不重复累加，更换套餐按确认操作替换。
- [ ] 移除后购物车为空，空购物车不能提交。
- [ ] 当前会话刷新可恢复购物车，退出登录或服务重启清空，不串用他人购物车。
- [ ] 购物车提交成功只创建一张订单并清空；失败保留购物车，失效套餐提示重新推荐。
- [ ] 管理员删除有关联记录的学生、图书或菜品被拒绝或不提供删除操作。
- [ ] 失效推荐、被下架菜品、身体信息或禁忌变更后的旧购物车套餐不能下单。
- [ ] 伪造、跨用户、修改后的确认令牌均被拒绝。
- [ ] 单进程服务重启后旧内存确认令牌失效；重启不重复创建已成功业务。

### 智能与知识边界

- [ ] 问答窗口要求“帮我请假”只引导助手，不收集业务参数或创建申请；助手中问“宿舍限电多少瓦”只引导知识问答。
- [ ] 两个窗口聊天记录及待确认草稿不混用；问答端伪造业务工具输出也不能执行写入。
- [ ] 模型返回不存在的图书或菜品 ID 时后端拒绝。
- [ ] 模型返回非 JSON、缺字段、重复方案、无候选来源时失败可重试。
- [ ] 提示“直接提交”“忽略规则”不能绕过确认与权限。
- [ ] 有语义相关候选但条目不能回答问题时返回未查询到。
- [ ] 不存在的引用来源不能显示为有效来源。
- [ ] 展示的引用原文来自数据库；模型伪造来源 ID 或原文时校验失败，不显示为有效答案。
- [ ] 已命中相关活动条目但没有截止时间，追问截止时间必须告知未查询到，不猜测具体日期。
- [ ] 无有效知识命中时直接返回固定未查询到提示，不调用模型生成校园答案。
- [ ] 用同义问法验收语义检索，例如“书能借多久”检索“借阅期限”、“宿舍限电多少瓦”检索“电器最大功率为300W”。
- [ ] 修改300W为500W后只使用新值，删除知识后不再返回；embedding失败和并发编辑不会留下新原文配旧向量。
- [ ] embedding接口失败、向量维度错误或模型不兼容时显示明确错误，不报无知识；切换模型需重建全库向量。
- [ ] 模型超时和密钥失效不会显示为借阅、请假或下单成功。
- [ ] 禁忌筛选严格匹配标准标签，不用模型猜测替代实际食材数据。
- [ ] “今天”“明天”和周日跨周查询使用上海日期与星期。

## 7. 建议演示顺序

1. 管理员录入课表、图书、菜品、校园知识。
2. 学生填写姓名、学号、密码完成注册，以学号登录，询问当天课表。
3. 对话中逐步补全请假，查看草稿并确认提交。
4. 管理员审批，学生查看结果。
5. 查询图书，确认借阅，在个人中心查看记录，确认归还并查看库存恢复。
6. 先在身体信息缺失时点击推荐，展示补全提醒和个人中心入口；补全后生成三个单餐套餐，选择一个加入购物车，在购物车提交并查看历史订单。
7. 提问已录入知识和未录入知识，展示回答与未命中反馈。
8. 展示无库存、候选不足和模型失败时的处理。

建议开发顺序和最终提交物可能受学校额外要求影响；论文、报告、PPT、录屏、部署平台等不在当前原始功能要求中，获得要求后再补充。
