# 智慧校园课设技术选型说明

更新日期：2026-10-15  
状态：Java、Vue、向量检索 RAG 已确认；Java 版本、框架、数据库、embedding 服务及打包形式待定

当前建议：Java 21 + Spring Boot + Vue 3 + SQLite，前端构建后由 Java 后端提供，交付可执行 JAR、外部配置和数据库文件。下面保留各方案比较，并具体说明智能功能与换电脑运行方式。

## 1. 先区分语言、框架和数据库

浏览器 Web 系统通常由前端、后端、数据库构成。本项目中的 LLM 是后端调用的外部接口，不需要自己训练模型，也不强制用 Python。

| 部分 | 在本课设中的工作 | 编程语言或工具 |
| --- | --- | --- |
| 前端 | 注册登录页面、对话、套餐卡片、购物车、管理表格 | HTML / CSS 描述页面与样式，JavaScript 或 TypeScript 处理交互；Vue、React 是前端框架/库 |
| 后端 | 权限、请假审批、库存变更、推荐校验、订单落库、LLM 调用 | Python + FastAPI、Java + Spring Boot 或 JavaScript/TypeScript + Node.js 后端框架 |
| 数据库 | 保存账号、图书、课表、菜品、知识及业务记录 | SQLite、MySQL 等关系数据库，使用 SQL 操作 |
| 开发工具 | 构建和启动前端项目、查看接口定义 | Vite、接口文档、调试工具等，不是新的业务系统 |

例如 `Vue 3 + FastAPI + SQLite` 表示：前端 Vue，后端 Python/FastAPI，数据库 SQLite。并不是用三种后端编程语言开发。

## 2. 后端语言和框架比较

| 方案 | 优点 | 代价 | 本课设的适用条件 |
| --- | --- | --- | --- |
| Python + FastAPI | 接口代码较简洁，参数校验和接口文档方便，处理 LLM 输出、营养计算和文本检索直接 | 仍需认真设计权限和事务；如果自己不熟悉 Python，后续答辩需要补语言基础 | 学校无限定、优先完成完整功能，或已有 Python 基础 |
| Java + Spring Boot | Java Web 课程中常见，分层、类型和事务工具成熟；便于结合 Java 课程答辩 | 项目配置与代码量通常更大，需要 JDK、构建工具及框架基础 | 学校要求 Java，或本人更熟悉 Java/Spring Boot |
| TypeScript + Node.js（如 Express / NestJS） | 前后端可使用同一语言，调用模型 HTTP 接口方便 | Express 的校验、分层等需自行搭配；NestJS 更规范但概念更多 | 本人已有 JavaScript/TypeScript Web 基础 |

三个方向都能完成当前全部功能。课设规模下没有必要仅为性能选择更复杂的框架，主要耗时通常来自模型调用。调用兼容 LLM 接口时 Java、Python 和 Node.js 均可使用 SDK 或 HTTP 请求；选择 Python 不会自动提升模型回答质量。

## 3. 前端方案

| 选项 | 区别与建议 |
| --- | --- |
| Vue 3 | 模板写法直观，表单、对话和管理表格适合配合 Element Plus 等组件库；在没有已有偏好的情况下建议采用 |
| React | 同样能完成项目；组件、状态管理和 JSX 写法不同，已有 React 基础时优先沿用，没必要为课设换框架 |
| 原生 HTML / CSS / JavaScript | 小页面初期依赖少，但本项目页面、表单和状态较多，手动维护重复逻辑的工作会增加 |
| JavaScript | 上手步骤较少，需通过规范和运行测试发现类型问题 |
| TypeScript | 在 JavaScript 上增加类型检查，帮助检查接口字段；需要额外学习类型写法，不能替代后端校验或测试 |

前端用 JavaScript 或 TypeScript，并不会限制后端采用 Python 还是 Java。建议 Vue 3；如果已有 TypeScript 基础则配合 TypeScript，否则可用 JavaScript 保持学习范围可控。组件库用于按钮、表格、弹窗，不决定业务逻辑。

## 4. 数据库方案

| 选项 | 特点 | 本课设建议 |
| --- | --- | --- |
| SQLite | 数据保存在一个本地文件中，无需安装独立数据库服务；支持事务和关系约束，但并发写入能力有限 | 单机演示、少量用户、便于提交运行时合适 |
| MySQL | 独立数据库服务，常用于多人 Web 系统，学校实验也可能指定 | 数据库课程要求 MySQL、已有基础或需多人部署时合适；需配置服务、账号及初始化脚本 |

两者都能实现当前数据模型，不需要为 LLM 再加一个数据库。知识问答首版采用向量检索 RAG，建议 SQLite 保存向量、Java 计算相似度，不强制加入独立向量数据库或 Redis。

ORM 是代码访问数据库的工具，数据库仍然是 SQLite 或 MySQL。例如 Python 可用 SQLAlchemy；Java 可用 MyBatis 或 JPA，开发时按最终路线选择一个即可。不要求同时使用多个持久化工具。

## 5. 可选整套方案

| 方案 | 组合 | 选择依据 |
| --- | --- | --- |
| A：优先简洁落地 | Vue 3 + Python/FastAPI + SQLite | 学校无限制、侧重业务演示和本地易运行 |
| B：Java 课程路线 | Vue 3 + Java/Spring Boot + MySQL | 学校要求 Java/MySQL，或本人已有相关基础 |
| C：统一 TypeScript | Vue 3 或 React + TypeScript/Node.js + SQLite 或 MySQL | 本人已熟悉 TypeScript 和 Web 开发 |

组合不是绑定的。Python 可以配 MySQL；Java 也可以配 SQLite，只是 Java 课程通常配 MySQL。如果学校只规定数据库为 MySQL，方案 A 可直接调整为 FastAPI + MySQL。

用户已选择 Java 和 Vue，不再考虑切换到 Python 或 Node.js 后端。考虑成品要移到另一台电脑运行，当前倾向调整为 **Vue 3 + Java/Spring Boot + SQLite**，不把 Java 与 MySQL 强制绑定。框架、数据库及版本仍为建议。

## 6. Java 如何实现 LLM 与知识检索

### 6.1 模型调用

Java 后端通过 HTTP 访问原始要求中的兼容模型地址，携带私有配置的 Key，将问题、必要上下文和受控工具描述发给模型，再解析返回结果。可使用 Java HTTP 客户端或兼容 SDK，不需要 Python 服务，也不需要本地训练或部署模型。

校园服务助手和校园知识问答是两个独立对话窗口。服务助手负责业务意图识别、多轮补全和调用 Java 业务服务，不接入知识 RAG；请假信息收集完整后由 Vue 渲染结构化表单卡片，确认才提交。知识问答仅使用 RAG，不具备业务提交工具。两者可复用同一聊天模型客户端，但分别配置路由、提示词、工具及会话上下文，超出职责的请求引导至对应入口。

请假、借阅在助手确认；归还在个人中心确认，下单在购物车提交，均由后端校验。若模型不支持原生工具调用，采用结构化 JSON 输出和 Java 校验解析即可，开发时验证实际兼容能力。

### 6.2 知识检索

```text
Vue 提交问题
  -> Java 调用 embedding 模型生成问题向量
  -> Java 读取 SQLite 中的知识向量，计算相似度并筛选相关原文
  -> 无有效命中：返回“暂未查询到相应的知识点。”
  -> 有候选：将候选交给 LLM 判断是否可回答并生成回答
  -> Java 校验引用来源，返回回答或未查询到提示
```

用户已要求首版实现向量检索 RAG。管理员按条维护标题和短文，保存时自动向量化；查询问题也通过同一 embedding 模型向量化。所有流程可以由 Java 实现。独立设计见 [RAG知识问答设计](RAG知识问答设计.md)。

### 6.3 SQLite 能否实现向量检索

需要分清三个环节：

| 环节 | 实现方式 |
| --- | --- |
| 文本向量化 | 由专门的 embedding 模型生成数值向量，SQLite 本身不生成；现有聊天模型是否有 embedding 接口不能直接假定 |
| 保存向量 | SQLite 可用 BLOB 或 JSON 文本保存向量，关联知识条目 ID，并记录所用模型和维度 |
| 按相似度查找 | 小数据量可在 Java 中计算余弦相似度；数据量大时可评估专门向量扩展或检索服务，原生 SQLite 不自动提供向量相似度索引 |

向量扩展并非 SQLite 默认功能，是否能随 Java JDBC 在目标 Windows 环境加载需要实际验证。对当前少量课设条目，建议 SQLite 保存向量、Java 计算相似度，不必引入额外原生扩展或独立服务。

例如知识条目写“图书借阅期限为 30 天”，用户问“书能借多久”，纯关键词可能漏检，语义向量更容易找到。向量检索改善的是表达匹配，不保证命中内容能回答问题；它仍可能返回相关但无答案的条目。即使采用向量检索，也必须设置并验证相关性门槛，再检查材料是否包含答案，不能始终把最相近的一条当作答案。

### 6.4 回答必须有数据库依据

已确认的要求是：只从管理员维护的数据库知识中检索回答，没有找到就明确告知，不能依赖模型自行编造学校规则。

- 无有效检索结果时，Java 直接返回“暂未查询到相应的知识点。”，不请求模型生成校园答案。
- 有命中但不足以支持问题时，同样返回未查询到；例如“社团活动安排”只有活动地点、没有报名截止日期，就不能推测截止日期。
- 有足够依据时，LLM 仅依据原文整理回答，页面同时显示来源标题和数据库原文摘录，后端核对来源与引用。
- 关键词和向量检索都需验证回答是否受原文支持，不能把“有引用”当作每句话都正确的证明。若需要严格只展示已有文字，可直接返回数据库原文摘录，避免生成摘要增加事实。

向量化已列为当前必做功能，但它改善的是语义匹配，不是回答真实性的保证。现有聊天模型及兼容地址是否提供 embedding 接口仍待验证，不能直接把聊天模型名称作为 embedding 模型使用；新增向量化配置应单独维护。

## 7. 换电脑运行的推荐交付方式

### 7.1 开发时与运行时分开

| 环境 | 所需工具 |
| --- | --- |
| 当前电脑开发及构建 | 建议 JDK 21、Node.js、Maven Wrapper、IDE；依赖版本固定在项目配置及锁文件中 |
| 另一台电脑只运行成品 | 浏览器和匹配的 Java 21 运行时；或者使用附带运行时的发行包 |
| 另一台电脑继续修改开发 | 源码和上述开发工具，按开发文档安装；无需复制 IDE 或其缓存 |

Java 21 是建议基线，具体 Spring Boot 版本要固定为与之兼容的版本，不随环境自动升级。Vue 只在构建时需要 Node.js，浏览器运行的是构建后的静态资源。

### 7.2 单个服务启动

开发时前后端可分别启动。发布时将 Vue 的构建产物纳入 Spring Boot 静态资源，再生成可执行 JAR；同一服务既提供页面，也提供 `/api` 接口。运行端不用安装 Node.js、Nginx 或启动两个项目。

建议发行结构（当前为方案示意，文件尚未生成）：

```text
campus-release/
  campus.jar
  start.bat
  config/
    application-local.properties.example
    application-local.properties       # 本地填写，不进入公开发行包
  data/
    campus.db                          # 首次初始化生成，或复制已有数据库
  README.md
  runtime/                             # 可选，针对目标平台提供 Java 运行时
```

运行时启动脚本先切换到自身所在目录，再使用系统 Java 或包内运行时启动 JAR 并启用外部配置；不写死盘符、用户名或开发目录。数据库目录须可写，页面使用相对接口路径，前端业务路由刷新由后端适当处理。默认通过 `http://localhost:8080` 打开，端口可配置。

外部真实配置由使用者单独配置或私下迁移，公开交付仅包含空密钥模板；不要把 Key 打进 JAR、前端或源码。

### 7.3 数据和运行环境一起迁移

1. 在当前电脑完成构建和业务验收，正常停止服务。
2. 如果要保留账号、请假、借阅和订单，复制发行目录及整个 `data/`；如果只需全新演示，交付空数据目录，由首次启动初始化。
3. 在目标电脑安装匹配 Java 运行时，或使用适用于其操作系统及 CPU 架构的附带运行时。
4. 单独填写本地配置，启动程序，使用浏览器访问；验证登录、已有记录和一次模型调用。

数据库初始化不能覆盖已有数据。程序更新通常只替换 JAR，保留 `data/` 和私有配置，再执行必要的版本化迁移。内存会话、推荐和购物车不迁移，重新登录及推荐即可。

AI 功能仍需联网访问配置的模型服务并使用有效 Key；数据库本地化不能让外部 LLM 离线运行。SQLite 驱动应随 JAR 提供，目标电脑不需要独立 SQLite 安装；选择的驱动和运行时须验证目标平台兼容性。

### 7.4 是否附带 Java 运行时

- 安装 Java 后运行：发行包较小，同一个 JAR 可跨支持的平台运行，但目标电脑需要安装或配置 Java。
- 附带 Java 运行时：在对应平台上可由启动脚本直接运行，减少目标电脑安装步骤；包更大，Windows/Linux、x64/ARM64 等需要分别准备，并核对运行时许可。
- 安装包是可选后续增强；不必为了本地课设直接引入复杂安装器。

已确认两台电脑都是 Windows，优先提供 Windows 启动脚本及对应运行包。CPU 架构在打包时核实；如果两台均为 x64，可共用 Windows x64 运行包。附带运行时仍须与目标架构匹配。

## 8. MySQL 和 Docker 何时更合适

| 交付方式 | 目标电脑的准备工作 | 建议使用场景 |
| --- | --- | --- |
| JAR + SQLite | Java 运行时，或使用附带运行时 | 当前课设单机演示、希望便于复制运行 |
| JAR + MySQL | Java、MySQL 服务、建库和导入数据 | 学校指定 MySQL 或已有数据库基础 |
| Docker Compose + MySQL | 安装并启动兼容 Docker 环境；加载镜像、准备配置及持久化数据 | 希望统一多人部署环境且接受 Docker 依赖 |

Docker 可以固定服务和依赖环境，但目标电脑仍需支持并安装 Docker，不是零安装；MySQL 容器数据也需备份和迁移，Compose 文件本身不包含已有业务数据。对当前简单单机课设，优先建议 JAR + SQLite，Docker 不列为必做。

最终需要确定 SQLite 或 MySQL，以及发行包是否附带运行时。用户提出的 Java、Vue 和跨电脑运行要求已作为正式方向同步，其余为可调整的实现建议。
